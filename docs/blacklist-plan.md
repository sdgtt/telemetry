# Plan: Add Blacklist for Known Issues in Report Generation

## Goal
Add a filtering mechanism to exclude or mark "known issues" from reports generated by `create_results_gist`. The blacklist should:
1. Support a file-based configuration (format TBD - JSON, TXT, etc.)
2. Support two display modes: "show as known issue" (for testing) and "hide completely" (for production)
3. Be maintainable and easy to update

The report generation flow is:
```
CLI (create_results_gist) → searches.py → markdown.py → gist.py
                              ↓
                        Elasticsearch
```

The filtering should happen in `markdown.py:generate_param()` where the report data is processed, specifically where these detail fields are populated:
- `dmesg_errors_found_details` (line 76)
- `pytest_failures_details` (lines 77-85)

### Step 2: Define blacklist file format (`known_issues.json`)

```json
{
  "version": "1.0",
  "rules": [
    {
      "type": "dmesg_error",
      "pattern": "some error regex pattern",
      "match_type": "regex",
      "description": "Known issue - tracked in JIRA-123",
      "scope": {
        "boards": ["board-a", "board-b"],
        "projects": ["project-x"]
      }
    },
    {
      "type": "pytest_failure",
      "pattern": "test_something",
      "match_type": "contains",
      "description": "Flaky test - being investigated",
      "scope": null
    },
    {
      "type": "missing_driver",
      "pattern": "iio:device0",
      "match_type": "exact",
      "description": "Expected on this board variant",
      "scope": {
        "boards": ["zynq-zc706-adv7511-fmcomms2-3"]
      }
    }
  ]
}
```

**Scope rules:**
- `scope: null` or omitted = applies to ALL boards/projects (global rule)
- `scope.boards: [...]` = only applies to listed boards
- `scope.projects: [...]` = only applies to listed projects (jenkins_project_name)
- Both can be combined: rule applies if board AND project match

## Display Modes

### Mode: "mark" (for testing)
```
#### DMESG Errors
- Error XYZ happened [KNOWN ISSUE: JIRA-123]
- Another real error
```

### Mode: "hide" (for production)
```
#### DMESG Errors
- Another real error
```

## Design Decisions

1. **Status impact is mode-dependent:**
   - In "mark" mode: known issues still count toward UNSTABLE/FAILURE status
   - In "hide" mode: known issues are excluded from status calculation

2. **Board/project-specific rules:** Yes, rules can specify:
   - `scope.boards`: list of board names the rule applies to
   - `scope.projects`: list of project names the rule applies to
   - If both specified, rule applies when BOTH match
   - If omitted/null, rule applies globally
